def fetch_by_ids(con, ids):
    if not ids:
        return {}
    placeholders = ",".join("?" for _ in ids)
    # ids come in as str (LanceDB). SQLite's id column is INTEGER; affinity will
    # coerce numeric strings, but convert explicitly to be safe and to keep the
    # dict keys consistent (str) for lookup.
    int_ids = []
    str_ids = []
    for i in ids:
        try:
            int_ids.append(int(i))
        except (ValueError, TypeError):
            str_ids.append(i)
    parts = []
    params = []
    if int_ids:
        parts.append(",".join("?" for _ in int_ids))
        params += int_ids
    if str_ids:
        parts.append(",".join("?" for _ in str_ids))
        params += str_ids
    where = " OR ".join("m.id IN (%s)" % p for p in parts)
    sql = f"""
        SELECT m.id, m.session_id, m.role, m.content, m.timestamp,
               m.token_count, m.display_order,
               s.display_name AS session_name, s.model AS session_model,
               s.started_at AS session_started
        FROM messages m JOIN sessions s ON s.id = m.session_id
        WHERE m.id IN ({placeholders})
        WHERE {where}

    cur = con.execute(sql, list(ids))

    cols = [d[0] for d in cur.description]

## Part 3 — Connecting TotalRecalls SSE conversations to Hermes + Honcho
The TotalRecalls Smart Search Engine (SSE) add-on downloads and indexes your AI conversations from 8 providers (ChatGPT, Claude, Perplexity, Gemini, Grok, DeepSeek, Mistral, Qwen) into a local library at:
```
C:\Users\break\TotalRecalls-download\Library\
  ├── chatgpt/home/<date> -- <title> -- <id>/conversation.json + conversation.md
  ├── claude/...
  └── ... (9 provider folders, 464 conversations)
```
SSE stores each conversation as `conversation.json` (structured: provider, account, messages with role/content/timestamp/model) plus a human-readable `conversation.md`.
### Why connect SSE to Hermes?
You now have **two local conversation corpora**:
| | Hermes sessions | SSE library |
|---|---|---|
| Source | Live Hermes chats (CLI, TUI, desktop) | Downloaded AI conversations from providers |
| Store | `%LOCALAPPDATA%\hermes\state.db` | `TotalRecalls-download\Library\` |
| Count | 164 sessions, 33,649 messages | 464 conversations (~multi-thousand messages) |
| Search | FTS5 + LanceDB hybrid index | SSE's own vec0 + BM25 index |
By ingesting SSE conversations into the same LanceDB hybrid index as Hermes sessions, you get **unified search across both**: one query returns hits from live Hermes chats *and* downloaded provider conversations, ranked together by RRF. Each SSE hit carries a `source_path` link back to the original `.md` file.
### Build the combined index
```bash
# Index Hermes sessions + SSE library together (rebuilds the LanceDB table)
python build_index.py
```
This:
1. Drops and recreates the LanceDB table with source-tagged schema (`source` = `hermes` or `sse`)
2. Embeds all 26,025 Hermes messages with all-MiniLM-L6-v2 (384-dim)
3. Parses and embeds all SSE `conversation.json` messages, tagged by provider
4. Stores `source_path` on each SSE record → direct link to the `.md` file
Both embeddings use 384 dimensions, so they share one index natively.
### Search across both corpora
```bash
# Search everything (Hermes + SSE)
