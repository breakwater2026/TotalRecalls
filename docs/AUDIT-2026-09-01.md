## 2. The Cloudflare fail-safe switch — located

It is **not a code flag** (zero matches for `failsafe` in the tree). It is the
**Cloudflare Pages deployment configuration**, documented at the top of `wrangler.toml`:

```
# For git-connected deploys, ALSO set in the dashboard:
#   Production branch: RedesignV7
#   Root directory:    (empty — repo root)
#   Build command:     cd site && npm ci --legacy-peer-deps && npm run build
#   Output directory:  site/dist
```

Mechanism: CF Pages serves a frozen build of the **RedesignV7** production branch while all
active development happens on **RedesignV8/V9**. The `[assets] directory = "site/dist"`
entry ("Solution A per Cloudflare diagnostic") is the code-side requirement. Verified
behavior: DNS → Cloudflare, every route 404s. **To go live later: point the production
branch at the release branch and redeploy — no code change needed.**

⚠️ Mismatch risk: `wrangler.toml` says production = `RedesignV7`, but the current work
branch is `RedesignV8` (with `RedesignV9`-titled commits). The frozen branch is one
iteration behind. Confirm in the CF dashboard before launch and update this comment.

## 3. Findings — prioritized

### 🔴 C1. The "free trial" funnel has no free artifact — the CTA is a lie ✅ FIXED (§3b)
The site repeatedly promises *"A free version is available now — download the app and test
it before paying"* (FaqSection, Pricing, /buy, /download, /legals, /pricing, /support,
/terms). But:
- The download button (`site/src/pages/download/index.astro:28`) points to
  `https://totalrecalls.app/downloads/TotalRecalls-1.0.0.zip` — a file that **does not
  exist anywhere** (no `.zip` in the repo; `dist/` contains only the raw EXE).
- `public/js/config.js:24-25` **hijacks every `data-tr-buy` button** and rewrites its
  `href` to the $24 Lemon Squeezy checkout. So the "Download the free version" button on
  the Pricing page literally sends visitors to a $24 payment page.
- Free-tier *limits* are implemented in the app (`licensing.py`: `FREE_PROVIDER_LIMIT=3`,
  `FREE_CONVERSATION_LIMIT=5`, `FREE_PROVIDER_IDS=("perplexity","chatgpt","claude")`), so
  the app is trial-ready — but **there is nothing to download** that is free.

**Fix (launch-blocking):** build a trial ZIP (EXE + README, trial-licensed by default),
publish it to a real URL (CF Pages public path or LS), point the download button at it,
and stop `config.js` from rewriting `data-tr-buy` on the *free* button (tag it
`data-tr-free` instead).

### 🔴 C2. License validation accepts ANY UUID → Pro unlocked for free
`totalrecalls/licensing.py:30-38`: `validate_license_key()` only checks UUID **shape**;
the comment says so ("Replace validate_license_key() with the real Lemon Squeezy license
API before launch"). Any visitor who types a random UUID gets Pro.
**Fix:** wire the Lemon Squeezy license verification API before any public launch.
(Consistent with beta, but this is the #1 thing to close at launch.)

### 🔴 C3. Dialogflow chatbot still promises a "14-day money-back guarantee" ✅ FIXED (§3b)
`site/serve.py:32-33` (GCP chat backend):
> "We offer a 14-day money-back guarantee… we'll issue a full refund — no questions asked."

This **directly contradicts** the free-trial-replaces-refund policy now used on every
static page. Also `serve.py:58` invites visitors to "ask about… refunds". And
`serve.py:35` advertises only 5 providers while the site says 8 (DeepSeek, Mistral, Qwen
missing). **Fix:** rewrite the three fallback strings to the free-trial language and the
8-provider list.

### 🟠 H1. Download page ships placeholder metadata ✅ FIXED (§3b)
`site/src/pages/download/index.astro:7-14`:
- `SHA256 = "0000…000"` (all zeros — the verify instructions are unusable and look
  negligent)
- `ZIP_SIZE_MB = 50` (guessed; real EXE is 18.2 MB)
- `ZIP_URL` dead (see C1)
- `RELEASE_DATE = 2026-08-26` (stale; current build 2026-09-01)
**Fix:** generate these from the PyInstaller build (the page comment already says to copy
them from `build/release.json` / `Get-FileHash`) — automate it so they can't drift.

### 🟠 H2. Four broken internal guide links on /download ✅ FIXED (§3b)
`download/index.html` links to `/guides/export-deepseek-chats/`,
`/guides/export-grok-chats/`, `/guides/export-mistral-chats/`,
`/guides/export-qwen-chats/` — none exist. Actual slugs are `/guides/deepseek/`,
`/guides/grok/`, `/guides/mistral/`, `/guides/qwen/`. (Rest of the site: **0 broken
internal links** across all 52 pages.)

### 🟠 H3. No build/deploy pipeline; committed site build is stale
- `.github/workflows/ci.yml` only runs tests+selftest on `main`. No workflow builds the
  EXE or deploys the site.
- `cloudbuild.yaml` / `cloudbuild.deploy.yaml` / `Dockerfile` exist (GCP path serving
  `site/dist` + Dialogflow `serve.py`), but CF Pages is the configured live target — two
  deployment paths, neither wired to CI.
- The committed `site/dist` predates the latest site commits (rebuilt locally during this
  audit: 52 pages, clean).
**Fix:** single source of truth — CF Pages (per wrangler.toml) — plus a CI job that
builds the EXE + ZIP and uploads the trial artifact.

### 🟡 M1. Private-repo link on a public page
`download/index.astro:41` ("watch the GitHub repo") → 404 (repo is private). Remove the
link or make the repo public.

### 🟡 M2. Landing-page demo video: `autoPlay` without `muted`, no `poster`, no `preload`
`landing/ProductShowcase.jsx:17-21`. Browsers block unmuted autoplay → the hero video
silently fails to play; also pulls the full MP4 immediately. **Fix:** add `muted
autoPlay loop playsInline` + a `poster` frame.

### 🟡 M3. GCP chatbot provider list is 5, site says 8
Covered in C3; the Dialogflow CX agent itself (agent id hard-coded in `serve.py:41`)
should be re-checked for the same.
